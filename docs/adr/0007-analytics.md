# ADR 0007: аналитика и экспорт

Дата: 2026-11-25 · Статус: принято

## Контекст

Этап 5. Владелец выбрал вариант "сводка дня" с плитками сверху и полосой фильтров и уточнил главное: оценивать
по сессиям и коммитам, чтобы видеть, где основной фокус, а где внимания не хватает. Данных в живой базе мало:
события за два дня, начало работы известно у 5 задач из 31 закрытой.

## Решение

**Третий вид той же оболочки:** `?screen=analytics`, клавиша `A`. Общие панель пункта, фильтр по проекту, палитра,
темы. Период в адресе (`period` или `from`/`to`). Фильтров два: период и проект; остальные по мере нужды.

**Каждый день:** фокус по проектам, активность по времени, сроки, статусы на сегодня. **Раз в неделю:** закрыто,
cycle time, план и факт. Плитки: сессии, коммиты, закрытые задачи, проекты с движением, просрочки.

**Внимание = среднее доли сессий и доли коммитов.** По одним сессиям orbit выглядел заброшенным: 4 сессии, но 28
коммитов. **Ожидание по приоритету считается по дням** среди проектов, которые уже идут: простая доля приоритета за
весь период обвиняла бы проект трех недель за три месяца.

**Коммиты читаются из git** (`commits`, миграция 0004), а не из журналов сессий: те недосчитали 8 из 27. Хранятся
только хеш и дата автора. `git` запускается с отключенными `fsmonitor` и проверкой подписи: чужой `.git/config` не
должен запускать программы. Сетевые папки запрещены (ADR 0004). `orbit serve` смотрит на файлы `.git` раз в 15 с и
запускает git только при изменении; демо-базы репозитории не читают.

**Метрики - SQL-файлы в домене** (`domain/sql/`, разбор в `docs/metrics.md`). Временные представления строятся на
соединение, в файл базы ничего не пишется. День считает `Clock` через функцию `local_day`: часовой пояс знает
только он. Правило отмен живет и в Python, и в SQL; их совпадение проверяет тест, как и даты работы с таймлайном.

**Честность вместо красоты.** Мало данных - график говорит, чего не хватает. Созданное сразу закрытым отдельно,
срок задним числом не план, сравнение с прошлым периодом только если записи тогда уже велись.

**Своя отрисовка: HTML и CSS.** Таблицы и списки со столбцами внутри, без библиотеки. Цвета проверены на
дальтонизм в обеих темах; каждое число есть текстом, подсказка под мышью только повторяет.

**Экспорт - звезда в CSV:** 4 измерения, 4 факта, словарь рядом. Только целые числа и даты: десятичная точка
зависит от языка системы. Пути, заметки, id и названия сессий не выгружаются. Живая база: предупреждение, файл
`PRIVATE.txt` и `.gitignore` в папке.

**История на полгода** (`seed --demo --half-year --until ДАТА`) отдельно от обычного демо, одна дата дает одни и
те же файлы. Эффекты в ней заложены, и это сказано в инструкции к дашборду.

## Рассмотрели и отказались

- **Recharts** 3.11.1: живой (релиз 23.11.2026, React 19), но 11 зависимостей, включая Redux Toolkit, и свои стили,
  темы и доступность поверх. Наши графики - полосы, столбцы и таблица.
- **Библиотека d3-scale:** нужны два числа, функция на 8 строк.
- **Постоянные представления в миграции:** без функции `local_day` они не работали бы в других программах.
- **Счетчик коммитов из журналов сессий:** неполный.
- **Экспорт одной широкой таблицей:** при соединении фактов суммы умножаются (fan-out).
- **Часы работы по длительности сессий:** ADR 0004.

## Последствия

- Новая мера = строки в `activity_facts.sql`; новый график = файл SQL, поле в `Analytics` и карточка.
- `GET /analytics` считает заново на каждый запрос. Замер: полгода истории - 100 мс, живая база - 40 мс.
- Испорченный адрес раньше ломал дерево: роутер подмешивал сырые параметры. `parseTreeSearch` теперь называет
  каждый ключ.

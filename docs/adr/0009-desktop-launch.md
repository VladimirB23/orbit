# ADR 0009: запуск с рабочего стола

Дата: 2026-11-25 · Статус: принято

## Контекст

`orbit serve` требует открытого терминала. Нужны: иконка, сервер без окна консоли, отдельное окно, повторный щелчок
без второго сервера, понятная остановка, автозапуск по желанию. Ограничение: Windows Smart App Control блокирует
неподписанные `.exe`, а отключать его нельзя (обратно включается только переустановкой Windows). Безопасность та же:
только `127.0.0.1`, без новых прав и адресов.

## Что сравнили

| | Ярлык на `pythonw` | Приложение Chrome (`Install page as app`) | Планировщик Windows |
|---|---|---|---|
| Запускает сервер | да | нет, только окно: без сервера страница с ошибкой | да |
| Окно без вкладок | да, `chrome --app=` | да | нет, нужен ярлык |
| Повторный щелчок | открывает окно | открывает окно | второй запуск надо запрещать отдельно |
| Smart App Control | `pythonw.exe` подписан | не при чем | тот же `pythonw` |
| Что остается в системе | файлы `.lnk` | запись в профиле браузера | задача, видна в `taskschd.msc` |
| Откат | `-Remove` или удалить ярлык | удалить приложение | удалить задачу |

Отказались без сравнения: Tauri, Electron, PyInstaller - новый неподписанный `.exe`, Smart App Control его не пустит.

## Решение

**Ярлык на `.venv\Scripts\pythonw.exe -m orbit app`** (`pythonw` - тот же Python, но без консоли).

- **Первый щелчок** становится сервером и открывает окно Chrome без вкладок (нет Chrome - Edge, нет обоих - обычная
  вкладка). **Следующий** находит работающий сервер по `/api/v1/meta` и только открывает окно. Другая база или чужая
  программа на порту - сообщение, а не молчание.
- **Два щелчка разом** разводит именованный mutex (замок Windows, который система снимает при смерти процесса). Одной
  проверки порта мало: пока первый обновляет базу, порт еще свободен, и второй ломал миграцию. Найдено живым запуском.
- **Остановка:** пункт `Stop Orbit` в меню Start или `orbit stop`. Работающий сервер держит метку
  `data/orbit-8420.run`; метка исчезла - он закрывает соединения и выходит сам. Адреса "выключись" в API нет, процесс
  никто не убивает. Метка чужого сервера не трогается.
- **Автозапуск** - такой же ярлык в папке Startup, без окна. По умолчанию не ставится.
- **Ярлыки** пишет `bin\shortcuts.ps1`: только папки текущего пользователя, без прав администратора и реестра.
  `-WhatIf` показывает, `-Remove` убирает. Ярлык с тем же именем, сделанный не нами, не трогается без `-Force`.
- **Одна иконка в taskbar.** Окно рисует Chrome, и Windows группировала его с Chrome. Теперь у ярлыка и окна один
  AppUserModelID (по нему taskbar группирует окна): ярлыку его пишет установщик, окну - `taskbar.py` снаружи, вместе с
  командой повторного запуска и иконкой. Не получилось - окно остается как есть.
- **Нет консоли - есть журнал:** `data/orbit.log`, а ошибка запуска показывается окном.
- Иконка `bin/orbit.ico` рисуется из `frontend/public/orbit.svg`: `node scripts/icon.mjs`.

## Последствия

- Папку проекта или `.venv` перенесли - ярлыки надо создать заново той же командой.
- Закрытое окно сервер не останавливает: он продолжает читать журналы сессий и коммиты.
- Только Windows. На других системах `orbit serve`.
- Гонка миграций остается возможной у двух команд из терминала в момент обновления; перед обновлением копия базы
  делается сама.

# Orbit — PRD

v0.8 · 2026-11-25 · этапы 1-6 готовы, публикация после "да"; модель: `docs/adr/0002-data-model-rules.md`, API и интерфейс: `docs/adr/0003-api-and-ui.md`, ссылки и сессии: `docs/adr/0004-links-and-sessions.md`, таймлайн: `docs/adr/0005-timeline.md`, отмена и поля: `docs/adr/0006-undo-and-fields.md`, аналитика и экспорт: `docs/adr/0007-analytics.md`, автоматические сроки: `docs/adr/0008-automatic-dates.md`, запуск с рабочего стола: `docs/adr/0009-desktop-launch.md`, будущие проекты: `docs/adr/0010-future-projects.md`

## Проблема

Проекты, сессии с Claude, советы и решения разбросаны по папкам, чатам и заметкам. Нет одного
места, где за минуту видно: что в работе, на каком этапе, какие сроки, что подвисло и в каких проектах.

**Главное:** контроль всех проектов, и тех, что в работе, и тех, что пока идеи, вплоть до отдельных сессий с Claude.
Видно, что в приоритете, а что можно удалить и забыть.

## Пользователи

- **Владелец**: смотрит статусы, планирует, правит руками в интерфейсе.
- **Claude** (общие сессии и сессии проектов): читает и обновляет данные сам через CLI, позже через MCP.

## Цели MVP

1. Одним взглядом видно все проекты и их этапы: статус, прогресс, сроки, короткий комментарий.
2. Claude меняет данные командой, интерфейс показывает изменение без перезагрузки.
3. Полный текст живет в Obsidian, из трекера заметка открывается в один клик (`obsidian://open`).
4. Каждое изменение пишется в журнал `events`. Это основа аналитики и история «кто что поменял».

**Не делаем:** логины, нескольких пользователей, облако, мобильное приложение, вложения.

## Модель данных

Иерархия как в Linear: **Project → Milestone (этап) → Task**, подзадачи через `parent_id`.

| Таблица | Поля |
|---|---|
| `projects` | id, slug (уникальный, = папка в `D:\Projects`), name, status, priority, start_date, due_date, summary (до 140 симв.), obsidian_path, repo_path, github_url, position, created_at, updated_at, done_at, archived_at |
| `milestones` | id, project_id, name, status, start_date, due_date, summary, position, created_at, updated_at, done_at |
| `tasks` | id, project_id, milestone_id?, parent_id?, title, status, priority, start_date, due_date, comment (до 280 симв.), position, created_at, updated_at, done_at |
| `events` | id, at, actor (`owner` / `claude` / `system`), entity, entity_id, action (`create` / `update` / `delete`), field, old_value, new_value, batch (действие), undoes (что отменяет) |
| `sessions` | id, external_id (id сессии Claude), project_id, started_at, ended_at, title, prompts, files, commits (числа), folder, topic_id (о каком проекте, если шла в другом) — импорт журналов сессий из Obsidian (ADR 0004, 0010) |
| `commits` | id, project_id, sha, committed_at — из git папки проекта (ADR 0007) |

- **Статусы** (одни для всех уровней): `backlog` → `planned` → `in_progress` → `paused` / `blocked` → `done` / `canceled`.
  Переходы свободные; закрыть или удалить элемент с открытыми потомками можно только с `--force` (ADR 0002).
- **Приоритет:** 0–4 (none, low, medium, high, urgent), как в Linear.
- **Прогресс** этапа = done / (все − canceled) по задачам; этап без задач — по своему статусу.
- **Факт:** начало - первый день в `in_progress` (и всего внутри), конец - день закрытия; из `events` (ADR 0005).
- **Сроки сами** (`auto_dates = true` в `data/orbit.toml`): пункт без срока получает его, когда становится
  запланированным или в работе; идеи и паузы без срока (ADR 0008).
- **Просрочено:** due_date < сегодня и статус не `done`/`canceled`.
- **Кто изменил:** CLI пишет `actor` из переменной `ORBIT_ACTOR` (для сессий Claude = `claude`), интерфейс — `owner`.

## Экраны MVP

1. **Дерево** (главный экран). Сверху сводка: в работе, заблокировано, просрочено, ближайшие 7 дней
   (нажатие фильтрует дерево); у свернутого проекта видны текущий этап и сигналы изнутри. Строки Project → Milestone → Task, раскрытие по клику и стрелкам.
   Колонки: название, статус, прогресс, старт, дедлайн, комментарий. У проекта под комментарием адрес
   папки, нажатие открывает ее в VS Code. Правка прямо в
   ячейке, быстрое добавление строки, фильтры (статус, просрочено, проект), поиск.
2. **Панель элемента** (drawer справа): адрес папки (VS Code, копировать), заметка Obsidian, все поля,
   у проекта сессии Claude с командой продолжения, история изменений из `events`.
3. Светлая и темная тема, горячие клавиши. `Ctrl+Z` отменяет последнее действие, `Ctrl+Shift+Z` возвращает.
   Ширина и состав полей настраиваются, у дерева и таймлайна отдельно.
4. **Палитра `Ctrl+K`**: перейти к любому пункту, открыть папку или заметку, выполнить команду.

5. **Таймлайн** (`G`): те же строки на шкале времени, план и факт, масштаб «Дни / Недели / Месяцы»;
   сроки тянутся мышью или клавишами, «Вернуть» отменяет.

6. **Аналитика** (`A`): фокус по сессиям и коммитам, сроки, темп; фильтры по периоду и проекту.

После MVP: вкладка "День" (планер и привычки), напоминания, канбан.

## Вкладка «Аналитика» (этап 5)

Встроенная, на живых данных. Сверху полоса фильтров (период, проект) и плитки: сессии, коммиты, закрытые
задачи, проекты с движением, просрочки. Определения метрик и SQL: `docs/metrics.md`.

- **Каждый день:** фокус по проектам (сессии и коммиты против приоритета, "мало внимания"), активность по
  времени, сроки (просрочено и 14 дней), статусы задач на сегодня.
- **Раз в неделю:** закрыто задач (throughput), cycle time, план и факт по этапам.

Мало данных - график говорит, чего не хватает. Отмененное, созданное сразу закрытым и сроки задним числом
показатели не улучшают.

**Tableau Public** - отдельно: `orbit export` → CSV → дашборд, только на вымышленной истории за
полгода. Инструкция: `docs/tableau.md`. Живого подключения к локальной SQLite у Tableau Public нет, поэтому
встроенная вкладка для работы, Tableau для показа.

## CLI

```
orbit status                      # in progress, overdue, upcoming deadlines
orbit tree [project]              # tree in the terminal
orbit project add <slug> --name "..." --due 2026-12-20 --obsidian "Inbox/<slug>/0. <slug> — Обзор.md"
orbit milestone add <project> "Core and CLI" --due 2026-11-28
orbit task add <project> "DB schema" --milestone 1
orbit set task 12 --status done --comment "schema + migrations"
orbit log --since 7d              # change history
orbit session list [project]      # Claude sessions imported from the Obsidian journals
orbit commit import               # commits from git of project folders
orbit stats [project] --days 30   # where attention goes: sessions, commits, closed tasks
orbit export --csv out/tableau    # facts and dimensions for Tableau, with a dictionary
orbit undo | redo                 # last action of the same actor, within 12 hours
orbit backup
orbit seed --demo                 # fictional data into data/demo.db
orbit seed --demo --half-year     # a long fictional history into data/demo-half-year.db
orbit serve                       # API + UI on http://127.0.0.1:8420, this computer only
```
У каждой команды есть `--json`: Claude читает машинный вывод, а не парсит таблицы.

## Архитектура

```
 Владелец (браузер)                 Claude (терминал)
   React UI  <-- SSE: "data changed"     orbit CLI (Typer)
       |  REST (FastAPI)                     |
       +------------> domain layer <---------+
                           |
                 SQLite: data/orbit.db  --> export CSV --> Tableau Public
```

- Одна доменная логика для API и CLI: правила статусов и запись в `events` в одном месте.
- **Живое обновление:** сервер дважды в секунду проверяет `PRAGMA data_version`; если базу изменил
  любой процесс (CLI, скрипт), шлет событие по SSE, и интерфейс перечитывает данные.
- База: путь из `ORBIT_DB`, по умолчанию `data/orbit.db` (в `.gitignore`).
  Для скриншотов и демо — `orbit seed --demo` с вымышленными проектами.

## Решенные вопросы

- Какие 3 графика нужны каждый день? Фокус по сессиям и коммитам, сроки, активность по времени (ADR 0007).
- Отдельный статус "на паузе" или хватит `blocked`? Статус `paused` для всех уровней (ADR 0002).
